## 实验 1：上下文、推理与工具的消融实验

### 做了什么

以 `Multinational Budget` 任务为例，分别移除历史上下文、推理、工具调用和工具结果，观察 Agent 是否能完成任务，以及迭代次数、工具调用次数和耗时如何变化。

### 截图中的结果

| 配置 | 是否完成 | 耗时 | 迭代次数 | 工具调用 | 推理步骤 | 观察 |
| --- | --- | ---: | ---: | ---: | ---: | --- |
| `full` | 是 | 28.52s | 4 | 7 | 2 | 看到了工具返回结果，最终回答正常 |
| `no_history` | 否 | 37.89s | 10 | 60 | 8 | 没有终止响应，循环更久、调用更多 |
| `no_reasoning` | 是 | 23.54s | 4 | 7 | 2 | 本次任务仍得到最终回答 |
| `no_tool_calls` | 是 | 24.01s | 1 | 0 | 1 | 图表功能标记为 `UNSUPPORTED` |
| `no_tool_results` | 是 | 51.85s | 7 | 16 | 6 | 图表功能标记为 `UNSUPPORTED`，耗时最长 |

### 我的理解

1. **历史上下文是稳定性的关键。** 去掉历史后，Agent 在 10 次迭代、60 次工具调用后仍未完成；这说明记住已经做过什么、拿到过什么结果，可以避免重复试错。
2. **工具调用和工具结果要成对看。** 没有工具调用时，Agent 无法获得外部观察；有调用但不给结果时，也会增加迭代和耗时。截图里的“完成”仅说明它给出了文本答案，并不表示基于可靠观察完成了需要图表的部分。
3. **“无推理”本次仍成功，不应过度推广。** 对这个具体任务，`no_reasoning` 与完整配置有相同的迭代和工具调用数；但单次消融不能证明推理在所有任务中都不重要，复杂规划任务仍可能依赖它。
4. **评估不只看最终答案。** 是否完成、是否有真实工具观察、调用成本、耗时和迭代次数都应该一起记录。

### 一句总结

> Agent 的能力不只是模型“会不会回答”，还取决于它能否带着正确的上下文，调用工具，并真正读取工具返回的观察。

## 实验 2：联网事实问答

### 任务与答案

问题：2024 年诺贝尔物理学奖得主是谁？

截图中的 Agent 经联网检索后回答：**约翰·J·霍普菲尔德（John J. Hopfield）** 与 **杰弗里·E·辛顿（Geoffrey E. Hinton）**。回答还概述了获奖理由：他们在人工神经网络与机器学习基础方面的贡献。

### 我学到什么

1. **适合检索的事实不要只靠参数记忆。** 获奖名单、发布日期、现任职位等容易变化或需要精确表述的信息，应优先检索权威来源。
2. **检索—整合—作答是一个闭环。** 截图显示 Agent 先判断“搜索结果足够”，再把来源中的姓名、获奖理由和背景压缩成中文答案。
3. **高质量答案应区分事实层次。** “谁获奖”是核心事实；获奖理由、研究贡献、机构信息是解释性补充。写回答时应先给结论，再给依据。
4. **仍要保留可追溯性。** 以后复现实验时，建议在输出中附上检索来源链接和访问日期，方便核查。

### 一句总结

> 联网让 Agent 能回答“最新且可核验”的问题，但真正可靠的关键在于：把检索结果变成带来源、不过度推断的结论。

## 实验 3：地理距离分析

### 截图中的结论

在“距离印尼最近的首都”分析中，排名第一的是：

| 排名 | 首都 A | 首都 B | 直线距离 |
| ---: | --- | --- | ---: |
| 1 | 吉隆坡（马来西亚） | 新加坡（新加坡） | 316.6 km |

截图还列出了前十组首都组合，并解释了为什么吉隆坡—新加坡距离最短：两地同在马来半岛附近，纬度接近，且经度差相对较小。文中使用 Python 的 **Haversine 公式**计算球面两点间的直线距离。

### 我学到什么

1. **自然语言问题要先澄清计算对象。** 这里的“距离”是首都坐标之间的球面直线距离，不是驾车距离、飞行航线距离，也不是国境之间的最近距离。
2. **工具把主观判断变成可复算结果。** 先收集各国首都坐标，再用统一公式计算和排序，结果才可检查、可复现。
3. **解释需要和计算相互校验。** 地理位置可以解释“为什么接近”，但最终排名应以实际坐标计算为准。
4. **数据口径会影响结论。** 截图补充说明：若把印尼首都按未来正式迁都的努山塔拉处理，最近首都仍是吉隆坡—新加坡（316.6 km）。实际项目中应明确采用的首都定义、坐标来源和时间点。

### 一句总结

> 遇到带有地理、数值或排序要求的问题，Agent 最可靠的工作方式是：明确口径 → 获取数据 → 用代码计算 → 用常识解释结果。

## Task 0 总结：我对 Agent 的初步工作流

```text
识别问题类型
  ├─ 稳定知识：可以直接回答，但要说明假设
  ├─ 时效事实：检索权威来源，再给出可追溯结论
  └─ 可计算问题：明确数据口径，用工具计算，再解释结果

全过程：保留上下文 → 规划必要步骤 → 调用工具 → 读取观察 → 检查输出
```
